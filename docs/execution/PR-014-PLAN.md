One native CPU behavior: an opt-in Store owns a World, one server-generated persisted owner epoch and durable sequence/revision watermarks. It accepts at most eight successful authoring batches of four operations for an initially empty world of at most eight slots. Only committed mutations consume keys. Exact retained retries return one of four durable receipts; altered payloads reject; missing keys below the high-water mark require resynchronization. Existing HTTP/SDK/policy retry profiles remain volatile and unchanged. This is not a general save package, network durability service, physics checkpoint, indefinite history system or migration of an existing persistent format.

Prepare complete bounded records before publication through the normal Coordinator observer. Reserve storage quota before writes, flush the immutable builtin asset before the journal commit, flush the commit before durable acknowledgement, and perform only noexcept in-memory publication afterward. Any ambiguous storage failure seals the Store and requires reopen/reconciliation; it must not claim a definite unchanged rejection or reuse a potentially durable key. Deterministic quota rejection before writes preserves the current state.

First-version bounded journal frames retain a full replay prefix, resolved identities and checkpoints, persisted epoch/high-water/low-water, canonical request and durable receipt window. Validate lengths, schema, strict types, integrity and complete prefix continuity. An incomplete trailing frame may recover the complete prefix; complete hash mismatch or corrupt selected checkpoint fails closed. Recovery constructs a private World and restores durable admission state before accepting any edit. Never reopen an older high-water as writable fallback after corruption.

Checkpoint compaction writes and flushes a replacement full package before publishing it atomically and reclaiming covered journal bytes. Reserve simultaneous old/new storage; interrupted compaction must leave the last durable state recoverable. A single exclusive writer owns each store. Paths are supplied only by the trusted caller, never read as executable or filesystem instructions from persisted data.

The documented durability model is abrupt process termination on supported local filesystems with successful native flush calls, not arbitrary power/device failure. Windows uses FlushFileBuffers; Linux file fsync and directory synchronization cover file publication. ## Reviewed format and failure details

The first-version frame is `OWJRN001` (8 bytes), payload length (little-endian u32), high-water (little-endian u64), SHA-256 of those 20 header bytes (32 bytes), bounded payload, SHA-256 of the authenticated 52-byte header plus payload (32 bytes), and `OWEND001` (8 bytes). Header integrity is checked before interpreting length or high-water. Payload is at most 256 KiB; total frame overhead is 92 bytes. Journal input is bounded to eight maximal frames. This integrity check detects accidental corruption; it is not authentication of an untrusted publisher.

Payload `OWPKG001` encodes configuration, private epoch, high/low watermarks, exact builtin asset descriptor/digest, full accepted prefix and four retained durable receipts. Integers are little-endian; strings/byte arrays have bounded u32 lengths. Recovered commands must parse and reserialize identically under protocol0.1, with exact world/epoch/sequence/revision and prefix continuity. Full replay validates recorded creation mappings and checkpoint bytes before a World is exposed. Unknown required frame/package schema fails closed. There is no previous released Store format to migrate; these files are distinct from diagnostic OWOBJ bytes.

Only fixed filenames `checkpoint.bin`, `journal.bin`, `checkpoint.tmp` and `writer.lock` are accepted. Caller-selected store paths are trusted; entries must be regular files and symlink/reparse entries are rejected. Local filesystem ownership is assumed; this is not a defense against an attacker concurrently rewriting the directory. Windows uses an exclusive writer handle; Linux uses a nonblocking flock. Recovery does not rewrite corrupt complete records. After successful validation it may repair an incomplete final journal frame or discard unselected bounded checkpoint scratch.

Configured quota defaults to 4 MiB and cannot exceed 8 MiB. Quota checks include simultaneous checkpoint/journal/scratch bytes before mutation. Native tests use a bounded logical quota, not actual filesystem exhaustion. Fault hooks are trusted native enum callbacks, never read from store data or exposed to the network. After-acknowledgement injection is explicitly called only after the example delivers and flushes a sanitized receipt to its parent process.
