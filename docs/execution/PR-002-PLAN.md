- Work item: **PR-002 — Versioned command schema**, under [the adopted implementation scope](AUTHORIZATION.md).

- Outcome: pure native parse/validate/serialize API for schema 0.1, with typed envelopes, operation variants and structured errors. The API receives no world, executor or capability context; success means `schema_valid`, never admission, authorization or commit.
- Contract source: [machine-readable schema](../../schemas/protocol-0.1.schema.json), [protocol design](../AI_CONTROL_PROTOCOL.md), [world identity](../WORLD_MODEL.md) and [ADR-0002](../adr/0002-authoritative-transactions.md).
- Scope: the documented envelope plus `entity.create` and `transform.set`; exact identity/revision/epoch/sequence/budget/scheduling values survive round-trip. Stable serialization is defined for this schema; no save/hash-format compatibility is claimed.
- Deferred: transport, authentication, server-issued epoch admission, quotas against live grants, world/entity existence, cross-world authorization, temporary-reference resolution, quaternion/scale execution invariants and all world mutations.
- Limits: 1,048,576 raw bytes checked before parse; container depth 32 with root one; 1–256 operations and count at most declared `budget.max_operations`; at most 64 CLI input files. Identifiers are ASCII per the schema, world/epoch/prefab up to 128 characters, temporary IDs up to 64. UUIDs use canonical lowercase hyphenated syntax.
- Integers: exact nonnegative uint64 for revisions, sequence, generation and blob budget; expiry is 1–4294967295; operation budget is 1–256. Reject decimal/exponent syntax for integer fields, booleans, negative or overflowing values; no coercion.
- Numeric vectors: finite binary64 components in fixed-length 3/4 arrays. Reject overflow and C++ typed NaN/Infinity before serialization can turn them into null. Quaternion normalization and invertibility are execution checks for later slices.
- Unknown fields (including caller `principal`), unsupported operations and duplicate decoded keys are rejected. Validate depth/duplicate keys with bounded SAX parsing before DOM construction.
- Error contract: `UNSUPPORTED_VERSION` for a string version other than 0.1; `UNSUPPORTED_OPERATION` for an unknown operation type string; `BUDGET_EXCEEDED` for byte/depth/operation limits or operation count above declared budget; `NONFINITE_VALUE` for number conversion overflow or non-finite typed values; `INVALID_SCHEMA` for remaining lexical, duplicate-key, type and field failures. Literal NaN/Infinity are invalid JSON and return INVALID_SCHEMA. Errors carry code, JSON-pointer path and optional operation index; lexical/parse-limit failures may use the root pointer. Do not echo untrusted values.
- Precedence: byte limit first, then lexical/SAX failures in input order, then schema/type validation. A padded valid envelope exactly at the byte limit is accepted; one extra byte is rejected. A depth-32 unknown structure reaches schema rejection; depth 33 is rejected by the parser budget. Integer 1 is accepted where allowed; 1.0 and 1e0 are not.
- Public example: `omniweft_examples --example protocol.reject_invalid --headless --seed 7 --verify --output artifacts/protocol.reject_invalid`. Repeatable `--input <file>` submits independent byte fixtures in one process. Per-input rejection is structured report data; a completed validation run exits zero even when inputs are schema_invalid.
