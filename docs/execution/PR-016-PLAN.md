# PR-016 content-addressed assets and provenance

Authorized by [the adopted roadmap](AUTHORIZATION.md). Branch `codex/pr-016-content-assets`, based on actual PR #22 merge `3b0204da63555deea238af34e3bf3e8a3ad39f4c`. Its tree matches reviewed delivery `3d95f2657ff1d09aedf05b077757e9f722c015bb`; all six post-merge checks and both native manifests were independently verified. PR-003 and PR-014 dependencies are integrated.

Implement one bounded native, single-owner asset Catalog and `assets.roundtrip`. Immutable asset identity is SHA-256 of a canonical versioned manifest containing decoded content hash/size and bounded media/source/license fields. Identical manifests deduplicate; different provenance produces distinct assets sharing one decoded blob. Provenance retains attribution data, without authenticating imported licensing assertions.

Mutations use typed Import, SetCurrentRoots, SetHistoryRoots, RemoveHistoryRoots and Collect commands with an expected catalog revision. Successful commands, including no-ops, advance the revision once. Stage validation, decoding, roots, catalog and receipt before publication; failure preserves the entire state. Queries return detached values. History roots are explicitly owner-held retention sets of full asset identities; collection follows those identities to their blobs. They do not automatically integrate with PR-012 undo or PR-014 persistence. Imported bundles never install roots, authority or revisions.

The new deterministic binary bundle is versioned and length-delimited. Export sorts manifest identities and blob hashes and uses raw bytes; import supports raw or bounded RLE8 pairs solely for this opaque content format. Only exact `blobs/<64 lowercase hex>` identifiers are accepted, with no normalization or filesystem extraction. Reject unknown versions/codecs, malformed/trailing data, duplicate entries, missing/extra blobs, hash/size mismatch and quota violations. Bound the bundle at 512 KiB, eight manifests/eight blobs, 64 KiB per decoded blob, 256 KiB decoded total, four named history root sets and eight references per root set. Check declared sizes before allocation and every RLE run against remaining output before appending.

The seed-7 example round-trips a generated fixture through an actual bundle file, imports it into a fresh Catalog, verifies canonical export equality and detached queries, and demonstrates same-manifest deduplication and shared content with different provenance. It removes current roots while history retains an asset, removes history while a different rooted manifest retains shared content, then collects the final blob and reimports valid data. Negative cases preserve full catalog snapshots and input bytes, including stale revision, malformed/missing/hash/path/schema/codec/decompression/quota failures. The Python oracle independently encodes/decodes bytes and computes content/manifest hashes against literal states; corruption selftests must reject misleading reports.

No external content is attached to World, replay, existing persistence, HTTP or SDK profiles.
